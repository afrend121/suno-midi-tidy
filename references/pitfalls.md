# 已知坑与错误恢复

按「先复现、再修、修完必须重新验证」的顺序处理，不要"试试这个试试那个"。
同一个问题连续修 3 次仍未解决，停下来把已尝试的方案摆清楚再决定。

## A. 原作者的坑（历史教训，别再踩一遍）

### A1. 把自己的代码 bug 当成"数据就是这样"
程序在处理音符时间时把应该**减掉**的偏移写成了**加法**，结果吉他被多推迟
17.7ms、贝斯 10.6ms、鼓 7.2ms。症状看起来像"源文件本来就对不齐"。

**防线**：拿合成素材（已知延迟 180ms）验证。实测值偏离已知真值就是代码问题，
不是素材问题。

### A2. 验证代码本身也会错
他写的检查代码也有 bug，最初告诉他"两份文件只差了 0.2 毫秒"，差点掩盖真问题。

**防线**：不要用自己的输出验证自己的输出。`selftest.py` 的断言全部对着
**故意插进去的错**写，而不是对着程序自己的输出去写。

### A3. 用不可信的力度当清理依据
原逻辑按"又短又弱"删杂音——但力度本身就是假的（与真实音量相关性 -0.001），
结果被删音符里 64% 在 WAV 里仍有声音。

**防线**：任何依赖 Velocity 的判断都不可靠。删音必须以 WAV 里的实际声音为依据。

### A4. 把"最弱但真实"的音当成杂音
安静前奏 -42dB、主歌 -24dB，用全曲最响处当基准，前奏 40 个真实音符被误删。

**防线**：局部窗口（默认前后 4 秒）+ 双条件 AND。`selftest.py::test_quiet_intro`
专门守这条。

### A5. 把整拍误差当成真偏移
循环鼓点会让互相关在"偏移量 ± 一个整拍"的位置出现同样高的峰。

**防线**：逐轨估计取中值；若峰值偏移超过 0.6 拍，在更靠近 0 的位置找
≥90% 峰值高度的局部峰优先采用；报告里把原始峰值一并列出（`ambiguous_beat_lag_ms`）。

### A6. 按旋律走向清理人声
"把前后跨度过大的音删掉"看起来合理，碰到复杂唱段会把真实主旋律一起清走。

**防线**：先看 WAV 的音高证据，再看音符之间的关系。不要反过来。

### A7. 把 Suno 的"前 32 小节免费版"当完整输出
官方免费体验版只能处理前 32 小节。用免费版验证完整流程时，后面小节的"缺失"
是工具限制，不是你的代码问题。

## B. 本技能开发中实际踩到的坑

### B1. 起音偏移系统性偏小 17ms
**症状**：合成素材真实延迟 180ms，报出 162.5ms（差 3 帧）。
**根因**：滑动 RMS 窗口是"滑入"音符的，起音被检测到窗口刚开始重叠的那一帧。
**修法**：`onset_envelope()` 在信号前补 `(frame - hop)` 个零。
**验证**：报出 179.95ms。

### B2. 力度重建后只剩 5 种数值、全挤在 96–127
**症状**：13 个音符本该有多种力度，结果只有 5 种且全部偏高。
**根因**：`note_db`（起点后 90ms 窗 RMS）与 `local_ref_db`（慢速包络第 90 百分位）
口径不一致，等于拿"起音峰值"减"包络平均值"，相对值全为正、被 clamp 到 0dB 上限。
**修法**：`measure_levels()` 用同一口径先测所有音符电平，`assign_local_ref()` 再在
这些电平之间取百分位。
**验证**：13 种、78–127。

### B3. 人声判据对假音符完全失效
**症状**：完全不存在该音高的假音符也拿到 25–35dB "证据"，阈值怎么调都拦不住。
**根因**：参考量用了全频段 200–4000Hz 的中位谱。串音的低通特性让频谱严重倾斜，
中位谱被高频低电平区拉低到 1.5e-2，任何东西除以它都是"高分"。
**修法**：参考量改为**同频段（0.5f0–3.5f0）内非谐波内容的第 95 百分位**。
**验证**：真实音 19.5–30.6dB / 假音 -12.9、-28.3dB，10dB 阈值隔离带很宽。

### B4. 低频音高落不进 FFT 频点
**症状**：65Hz（C2）这种低音，±3% 容差只有 ±2Hz，而 8192 点 FFT 在 22050Hz 下
一个频点是 2.7Hz —— 频带掩码可能为空，能量恒为 0。
**修法**：容差按分辨率自适应，`tol = max(0.025, 1.5 * bin_hz / f)`。

### B5. 包络分块计算时的内存峰值
**症状**：5 分钟歌曲若一次性物化 `(帧数 × frame)` 的中间数组，会吃掉几百 MB。
**修法**：`rms_envelope()` 分 4096 帧一批处理，峰值内存与歌曲长度无关。

## C. 遇到问题时的排查顺序

1. **先跑 `selftest.py`。** 绿了说明引擎没坏，问题在素材或参数；红了说明改坏了代码。
2. **看 `report/*_summary.json`** 里的 `offset.correlation`。相关性很低（<100）
   说明这条轨的起音检测不可信，改用另一条乐器轨对照。
3. **看 `*_removed_notes.csv` 逐个回听。** 删错了就调阈值重跑，别在 DAW 里手工补。
4. **力度不对先看是不是复调。** 报告里 `polyphonic_uncertain > 0` 表示同轨近同时多音，
   力度取自混合音频，本来就无法精确归属——这是物理限制，不是参数问题。
5. **不要改 `tidy_core.py` 去迁就某一个素材。** 改之前先在 `synth_fixture.py` 里加
   一组会失败的合成素材，让问题可复现、可回归。

## E. 打包与上架

### E1. 技能包内不能含 `.bat` / `.cmd`（真实踩坑）

**现象**：技能市场（SkillHub 等）在上传阶段直接拦截，提示不允许提交含
`RUN_WINDOWS.bat` 的文件。审核不会给你解释是哪条规则。

**原因**：`.bat` / `.cmd` 属于可执行脚本。准入审核把「包内可执行文件」当作
风险项，无论内容多无害都不放行。

**处理**：

1. `scripts/start_gui.py` 是 `.bat` 的 Python 替代品，跨平台、**零外部进程调用**，
   用 `python scripts/start_gui.py` 启动界面，`--check` 只做环境自检。
   **它是唯一对外文档化的启动入口。**
2. `RUN_WINDOWS.bat` 仍然保留在作者直发的包里（那份不走平台审核，且它的
   自建 `.venv` + 自动装依赖对非技术用户很友好）。
3. `build_skillhub.py` 里的 `BLOCKED_SUFFIX` 是**硬拦截**：`.bat` / `.cmd` /
   `.exe` / `.ps1` / `.sh` 等一律不进公开包，并在自检里断言。
   不要靠"记得手工删"——那正是这次出错的原因。

**同类注意**：`.ps1`、`.vbs`、`.wsh`、`.jar`、`.sh`、`.command` 也在拦截清单里。
以后想给技能加"一键启动"之类的便利，用 `.py` 写，别用 shell/batch 脚本。

### E2. 打包脚本"顺手格式化"会改坏代码

第一版擦除逻辑里加了折叠连续空行的正则，结果把 Python **PEP8 顶层定义之间的
双空行全删了**。现在 `build_skillhub.py` 只做两件事——删命中整行、替换命中片段，
其余字节（空行、缩进、CRLF/LF、末尾换行）一律不动；并且用
`audit_against_source()` 逐行比对产物与源码，任何**非擦除规则**造成的差异直接判 FAIL。

### E3. 上架前必跑

```bash
python build_skillhub.py --out ./dist-hub --flat-zip
```

自检全绿再上传。它会检查：命名合规、`description` 长度、私钥泄漏、作者本机绝对
路径、Python 语法、**平台禁用可执行文件**、**文档是否还指向未打包的 `.bat`**、
以及与源码的差异来源。
